Checkpoints and recovery

A pipeline checkpoint is one consistent moment across every GPU

A manifest, written last

Each stage saves with DeepSpeed's own checkpoint. A manifest listing every file's fingerprint is written only when all have finished.

Everything to continue exactly

Weights, optimizer, schedule, random-number state and data position. A fresh pipeline that loads it matches the original bit for bit.

Checked before anything loads

A wrong plan, a missing file or a changed file is rejected before any stage is touched; each stage re-checks its own files.

Recovery rebuilds everything

If a worker died, loading tears the pipeline down and rebuilds it on the same machines, then loads.

A folder without a manifest is an unfinished save and is never loaded, so a crash mid-save can't produce a half-new checkpoint. Loading is the only way out of the locked state after a partial optimizer step.
