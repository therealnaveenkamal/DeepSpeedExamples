Architecture

A driver that plans; stages that do the work

Your training script

Calls initialize(), then train_batch() in a loop

Plan compiler

Splits layers into stages; sets each stage's GPUs

Coordinator (driver)

Sends each stage one command per step

Stage 0

Embedding + layers

2 GPUs, data parallel, ZeRO-2

Stage 1

Layers

2 GPUs, tensor parallel

Stage 2

Layers

2 GPUs, sequence parallel

Stage 3

Layers + output head

4 GPUs, expert + tensor parallel

one command per stage, per step (its whole 1F1B op list)

Each stage = one Ray worker per GPU, running a stock DeepSpeed engine. Neighbours exchange activations (→) and gradients (←) directly over NCCL.

The driver never holds weights or activations; only losses and ok/failed statuses come back to it. Each stage has its own torch.distributed world owned by DeepSpeed (for data/tensor/sequence/expert parallel inside the stage), plus two extra NCCL groups per GPU for stage-to-stage traffic, one per direction. The example shapes are illustrative: every stage's GPU count and parallelism is declared per stage.
